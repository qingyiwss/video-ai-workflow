# 一、环境准备

## 1.1 先跑检测

```bash
python setup.py --check-only
```

**它会告诉你：**

- Python 版本够不够
- 缺哪些包
- ffmpeg / Chrome / Node 找了没
- 你的硬件适合哪个 TTS 方案

**看完再决定装什么，别一上来就 `pip install`。**

---

## 1.2 硬件分档

| 你的机器 | 推荐方案 | 一句耗时 | 90 秒片子 |
|---|---|---|---|
| 有独显（NVIDIA/AMD，显存 ≥6GB） | **本地 GPU** | 3.9 秒 | 10 分钟 |
| 只有核显 | 本地核显 | ~12 秒 | 30 分钟 |
| 没显卡但 8 核 + 16GB | 本地 CPU | 188 秒 | 2-8 小时 |
| 老旧笔记本 | **edge-tts** | 1.7 秒 | 4 分钟 |

**关键：换 TTS 不影响卡字率、画面、节奏。**

实测 CosyVoice3 净 cps **5.01**，edge-tts **5.06** —— 差 1%。

**唯一的区别是「声音是不是你自己的」。**

---

## 1.3 装依赖

```bash
python setup.py
```

**会自动做：**

1. 检查 Python ≥3.9
2. `pip install` 缺的包
3. 检查外部工具，缺了给安装提示
4. 检测硬件，列出 TTS 方案让你选
5. 按选择下载模型（本地方案才需要）
6. 跑一次 3 秒测试音频

**不会自动做（需要你手动）：**
- 装 ffmpeg / Chrome / Node（有系统级影响）
- 录参考音（只有你能做）

## 1.4 如果你选了本地模型

**需要三个文件：**

### ① audiocpp 引擎

从 GitHub Releases 下载，放到 `vendor/audiocpp/`。

```
vendor/audiocpp/audiocpp_cli.exe
```

### ② CosyVoice3 模型（2.1 GB）

```bash
# 手动下载
# https://huggingface.co/cstr/cosyvoice3-0.5b-2512-GGUF
# 保存为 models/cosyvoice3-q8_0.gguf
```

或设置环境变量指向已有文件：
```bash
export KAZI_MODEL=/path/to/cosyvoice3-q8_0.gguf
```

### ③ 参考音（20 秒，你自己的声音）

**这是最关键的。**

```
my-voice/
├── ref.wav      15-30 秒，你自己念的
└── ref.txt      这段音频的文字（逐字写下来）
```

**录音要求：**

| 项 | 要求 |
|---|---|
| 时长 | 15-30 秒（太短音色不稳，太长没必要） |
| 格式 | WAV，16kHz 以上，单声道或立体声 |
| 环境 | 安静，无背景音乐，无回声 |
| 语速 | 正常，别刻意放慢 |
| 内容 | 什么话都行，但**必须写下来**（`ref.txt`） |
| 一口气 | 别中途停，别念稿停顿 |

**⚠️ `ref.txt` 必须和音频一字不差。** 差一个字，克隆效果就差很多。

**参考文案例子：**
```
我最近在想一个问题，为什么有些工具用起来很顺手，有些用两次就放下了。
后来发现差别不在功能多少，而在它有没有替你省掉那些真正烦人的步骤。
```

# 三、做自己的片子

## 3.1 建项目目录

**一条片子一个目录**（重要）。

```bash
mkdir my-video && cd my-video
```

**命名规范：**
```
<方向>-<关键词>/

v-sync/     竖屏 · 同步
h-deploy/   横屏 · 部署方案
```

方向：`v` 竖屏 / `h` 横屏 / `s` 方形。

---

## 3.2 写稿

**格式：**

```
＃ 这是注释
＃ 目标：90 秒 / 372 字 / 20-25 句

[01 开场]
先说一个词，叫*卡字*，就是画面动的那一下，正好跟字对上。 | 0.5
它念到哪个字，画面同时也到，一秒都不差。 | 0.6

[02 原理]
声音比画面早四十五毫秒，人的耳朵就能察觉到。 | 0.4
```

**语法：**

| 写法 | 含义 |
|---|---|
| `[01 段落名]` | 段落/章节，一个段落对应一个画面场景 |
| `*关键词*` | 画面要卡在这个词上。**每段恰好 1 个** |
| `\| 0.5` | 这句收声到下一句开口的空白（秒） |
| `{念法=>字幕}` | 左边给配音念，右边给字幕显示 |
| `＃` | 注释行 |

**四条硬规则：**

| 规则 | 阈值 | 为什么 |
|---|---|---|
| 平均句长 | **15-24 字** | 少于 15 字停顿会累积 |
| 碎句占比（≤4 字分句） | 18-22% | 太低像书面语，太高像 AI |
| 关键词 | **≥2 字，动词或变化** | 单字只能画成插图 |
| **关键词距段首** | **≥1.65 秒** | 这是卡字的物理下限 |

**⚠️ 最后一条最容易漏。** 关键词不能放在段落第一句的开头，否则画面的「进场」和「上一段退场」会打架，卡字永远调不好。

**正确做法：**
```
[01 开场]
先说一个词，叫*卡字*，就是画面动的那一下。    ← 关键词在第 6 个字（≈1.2 秒）
```
```
[01 开场]
它念到哪个字，画面同时也到。                    ← 先铺垫
这叫*卡字*，一秒不差。                          ← 关键词在后面（≈3 秒）
```

## 3.8 画面

### 写 `scene-def.json`

```json
[
  {
    "sid": "01",
    "kind": "hero",
    "theme": "paper",
    "first": "01_01",
    "last": "01_02",
    "data": {
      "title": "卡字",
      "kicker": "先说个词",
      "note": "画面动的那一下，正好跟字对上"
    },
    "chap": {"num": "01", "cn": "开场", "en": "WHAT"}
  },
  {
    "sid": "02",
    "kind": "compare",
    "theme": "dark",
    "first": "02_03",
    "last": "02_04",
    "data": {
      "title": "为什么是 45 毫秒",
      "left": {"title": "看见", "desc": "125 ms", "color": "#7A8971"},
      "right": {"title": "听见", "desc": "45 ms", "color": "#C99B3F"}
    }
  }
]
```

**`first` / `last` 对应 `timeline.json` 里的 `tag`**（形如 `01_03`）。

### 10 种场景类型

| kind | 用途 | 竖屏 | 横屏 |
|---|---|---|---|
| `hero` | 开场、结论、金句 | 大字居中 | 左大字右说明 |
| `points` | N 个要点 | 纵向 | 横向 |
| `steps` | 步骤流程 | 纵向 | 横向 |
| `compare` | A vs B | 上下 | **左右** |
| `number` | 大数字 | 居中 | 居中 |
| `quote` | 引用原话 | 居中 | 居中 |
| `before-after` | 改前改后 | 上下 | **左右** |
| `list` | 清单（带勾） | 纵向 | 纵向 |
| `product` | 产品展示 | 上名下特性 | 左名右特性 |
| `cta` | 行动号召 | 居中 | 居中 |

### 主题色

| theme | 底色 | 文字 |
|---|---|---|
| `paper` | 纸白 #F2EFE6 | 墨黑 #1A1C1F |
| `dark` | 深蓝 #1F3B4D | 米白 #F2EFE6 |
| `red` | 暖红 #A8231A | 米白 |

```bash
# 只渲一段（先验证）
node ../canvas/render.cjs . 9:16 still 12.5 out.png
```

**比例可选：`9:16` / `16:9` / `4:3` / `1:1`**

## 3.9 混音

```bash
python ../tools/mix.py . --bgm bgm.wav --out mix.wav
```

**做什么：**

| 项 | 参数 |
|---|---|
| BGM 说话时 | 比人声低 **15 dB** |
| BGM 空当时 | **+6 dB**（即低 9 dB） |
| 空当阈值 | 0.55 秒 |
| 1-4kHz | 各低 2-2.5 dB（让人声清楚） |
| 音效 | 人声 RMS -8 dB |

**然后归一化（关键）：**

```bash
# ① 压缩
ffmpeg -y -i mix.wav -af \
  "acompressor=threshold=-24dB:ratio=4:attack=5:release=150:makeup=14" \
  -ar 48000 _c.wav

# ② 限幅
ffmpeg -y -i _c.wav -af "alimiter=limit=0.87:attack=2:release=30:level=0" \
  -ar 48000 _l.wav

# ③ 精确增益（目标 -14 LUFS，峰值不超 -1.2）
ffmpeg -i _l.wav -af loudnorm=print_format=json -f null -
# 看输出里的 input_i 和 input_tp，算：
#   gain = min(-14.0 - input_i, -1.2 - input_tp)
ffmpeg -y -i _l.wav -af "volume=+X.XdB" -ar 48000 mix-final.wav
```

**⚠️ 不能只做 loudnorm。** 实测 LRA 9.3 时 loudnorm 只能到 -16.4。

---

## 3.10 合成

```bash
ffmpeg -y \
  -framerate 60 -i frames/f%05d.png \
  -i mix-final.wav \
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p \
  -colorspace bt709 -color_primaries bt709 -color_trc bt709 \
  -c:a aac -b:a 192k -ac 2 \
  -shortest -movflags +faststart \
  FINAL.mp4
```

### ⚠️ 闸门 4：改过画面必须重测卡字率

**改画面 = 改变帧间差异 = 改变「前一秒」的动量。**

**实测：修完 7 个视觉问题后，卡字率从 100% 掉到 30%。**

```
改画面 → 局部重渲改动的段 → 测卡字率 → 过了才继续
```

只渲改动的段：
```bash

```

### 抽帧看画面

**机器只测「在不在动」，不测「画面对不对」。**

每段抽 4 帧：

| 抽哪一帧 | 看什么 |
|---|---|
| 进场 +0.3s | 场景建立起来了没 |
| 关键词前 1s | 前一秒干净吗 |
| **关键词时刻** | **动作到位了吗** |
| 段末 -0.3s | 退场干不干净 |

```bash
ffmpeg -ss 3.0 -i FINAL.mp4 -frames:v 1 check-01.png
```

**实测查出 7 个问题，2 个致命（主题色串台、场景重叠）。这些卡字率一个都测不出。**

# 四、常见问题

## Q: 卡字率只有 60-70%

**看 PITFALLS 坑 20。** 99% 是场景动作太小（`scale 0.94→1` 这种），**把动作换成真的**（位移、展开、弹出）。不要加全屏亮度遮罩 —— 那是造假信号。

## Q: 声音不是我的

**edge-tts 不能克隆音色。** 要自己的声音必须用本地模型（需要显卡或耐心）。

## Q: 渲染很慢

**每帧要启动 Chrome 截图。** 60fps × 90 秒 = 5400 帧，约 12 分钟。

想快：
- 降帧率到 30（但卡字精度会差）
- 减小分段（`render.cjs` 支持分段并发）

## Q: 字幕和声音对不上

**先跑 `caption_check.py` 看是哪一类问题：**
- 「出现晚于开口」→ 调 `captionFor` 的提前量
- 「收声前就消失」→ 调 chunk 的结束时间
- 「逐字变亮偏了」→ 对齐数据有问题，重跑 align

## Q: 能不能不用 60fps

**可以，但卡字精度会降。**

60fps 下「关键词前 3 帧」= 50ms，正好是 ITU-R BT.1359 的听觉-视觉同步阈值。
30fps 下 3 帧 = 100ms，已经能感觉到不同步。

**建议保 60fps。**

## Q: 我的稿子写不出来

**先抄 `demo/script.md` 的结构**，改内容。
或者看 `工作流.md` 第 2 步的「四版迭代」和「禁用清单」。
