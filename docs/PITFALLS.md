# 写稿阶段

## 坑 1：时长和字数互相矛盾

**症状**：稿子开头写「目标 70 秒 / 400 字」，配完音发现是 96 秒，超 37%。

**原因**：
```
400 字 ÷ 5.0 cps = 80 秒语音
+ 8.8 秒停顿 + 3.1 秒片头尾 = 92 秒
```
这两个数从一开始就不可能同时成立。

**修法**：写稿前先查表。

| 目标片长 | 需要字数 | 大致句数 |
|---|---|---|
| 60 秒 | 229 字 | 12-15 句 |
| 70 秒 | 277 字 | 15-18 句 |
| 90 秒 | 372 字 | 20-25 句 |
| 120 秒 | 507 字 | 28-33 句 |
| 150 秒 | 637 字 | 35-40 句 |

公式：`片长 = 字数 ÷ 净cps + 0.34×句数 + 3.1`

---

## 坑 2：碎句率靠拆句子凑，结果越拆越慢

**症状**：想提高「碎句率」到 20%，把句子拆成 7 个字一句。结果句数暴涨，停顿累积，90 秒的片子硬是降到 80 秒还下不来。

| 版本 | 平均句长 | 句数 | 停顿合计 | 总长 |
|---|---|---|---|---|
| 错的做法 | 6.9 字 | 50 | 20.9 秒 | 88 秒 |
| 对的做法 | 16.7 字 | 26 | 9 秒 | 81 秒 |

**原因**：碎句率指的是**句子内部**的短分句占比，不是句子本身的长度。

**修法**：
```
❌ 错（句号多）：
  先说个词。
  先说卡字。
  就是画面动的那一下，跟字对上。

✓ 对（逗号多，句子长）：
  先说个词，叫卡字，就是画面动的那一下，正好跟字对上。
```

**三项指标必须同时满足**（只量一个是最大的错）：

| 指标 | 目标 |
|---|---|
| 平均句长（到句号） | **15-24 字** |
| 平均分句（到逗号） | 7-8 字 |
| 碎句占比（≤4 字） | 18-22% |

## 坑 3：`say` 里没标点，停顿规整完全失效

**症状**：跑停顿规整报「0 处改动」，但实际有 22 处该剪。

**原因**：输入数据用 `"".join(w["u"] for w in words)` 拼的，标点已经丢了。

```
拼出来： 它念到哪个字画面同时也到一秒不差
应该是： 它念到哪个字，画面同时也到，一秒不差。
```

停顿规整靠标点找断点，找不到就静默跳过。

**修法**：直接用带标点的原文。
```python
say = L["text"]        # ✓
say = "".join(w["u"] for w in L["words"])   # ✗
```

**检查方法**：`say` 里应该有 `，。？！`。

## 坑 4：只用首字符找标点，会漏掉一半

**症状**：一个有 2 个逗号的句子，只处理了 1 个。

**原因**：
```python
# 原稿 `*定了个算法*，` 中间是 `*，`，首字符是星号
p = between[:1]     # ✗ 拿到的是 `*`
```

**修法**：在这一小段里搜标点。
```python
p = next((ch for ch in between if ch in RULE), None)   # ✓
```

# 配音阶段

## 坑 5：`pace.py` 要的是目录，不是文件

**症状**：传两个 wav 路径直接报错 `required: src, dst`；传单个文件报「没有 L*.json」。

**原因**：这个工具的接口是「目录进目录出」，而且输入结构固定为：

```
输入目录/
├── lines/
│   ├── L0001.wav
│   └── L0001.json       {"say": "念法", "dur": 3.2}
└── align/
    └── <sha1前16位>.json
```

**修法**：先建适配目录。
```python
SRC = BASE/"pace-in"
(SRC/"lines").mkdir(parents=True, exist_ok=True)
for i, L in enumerate(sel, 1):
    shutil.copy2(BASE/"lines"/f"{L['tag']}.wav", SRC/"lines"/f"L{i:04d}.wav")
    (SRC/"lines"/f"L{i:04d}.json").write_text(
        json.dumps({"say": L["text"].replace("*",""), "dur": L["dur"]}))
```

**实测效果**：39 句里 36 句有剪短，省 4.8 秒。

**⚠️ 之后时间表全变，必须重新对齐 + 重新渲染。**

## 坑 6：静音门槛太严，把长停顿切成两段

**症状**：一个 550ms 的停顿，工具只测到 420ms，剪完还剩 100ms 零头。

**原因**：阈值 -32 dB 时，换气声（约 -30 dB）被判成「有声」，把停顿切开了。

**修法**：阈值放宽到 **-36 dB**，并合并 **< 80ms** 的有声缝隙。

```python
THR_IN = -36.0
# 把 < 8 帧（80ms）的有声段改回静音
```

---

## 坑 7：对齐器把静音算进某个字

**症状**：`找到原因了，是切屏` 里「了」标成 0.54-1.68 秒（1.14 秒），实际只有 120ms。

**原因**：对齐器把 1.02 秒静音全算进了「了」。

**修法**：不信 `align` 的 `s`/`e` 算间隙，**扫全句的长静音**。

```python
SCAN_THR = 0.28    # 只处理比这长的静音段
MAX_INNER = 0.25   # 没有标点的位置，允许的最大停顿
```

---

## 坑 8：剪静音的范围越界，把后面的字剪没了

**症状**：`找到原因了，是切屏` 变成 `找到原因了`，`是切屏` 整段消失。

**原因**：剪切起点从「最安静那一帧」往后算，起点在静音中间，长度又超过了可用静音。

**修法**：三重保险。
```python
c0_ = max(cs2, min(c0_, ce2 - cut))          # ① 落在静音段内
if (db[i_a:i_b] > THR_IN).sum() > 2:          # ② 这段真的没响声
    c0_ = 最安静的位置 - 一半
# ③ 接口处做 8ms 淡入淡出，避免咔哒声
```

---

## 坑 9：对齐器把最后一个字算到句尾之外

**症状**：闸门检查报「超出句边界」，最后一个字比句尾晚 0.13 秒。

**原因**：句子边界来自配音时的时长记录，对齐器算出的最后一字结束时间可能更晚。

**修法**：把超出的部分钳回句尾。
```python
if times:
    last_te = max(te for _, te in times)
    if last_te > (abs_end - abs_start) + 0.005:
        times = [(min(ts, abs_end - abs_start - 0.01),
                  min(te, abs_end - abs_start)) for ts, te in times]
```

## 坑 10：`max_tokens` 会截断内容

**症状**：想加快生成速度，设了 `max_tokens=200`，结果句子被截断。

**原因**：这个参数是硬上限，不是目标。

**修法**：不要用它做加速。要快就换后端（见 docs/TTS-PLANS.md）。

# 对时间阶段

## 坑 11：关键词全在段首，卡字永远修不好

**症状**：15 个关键词，8 个在段落第一句的第 0.3-0.8 秒。卡字率怎么调都上不去。

**原因**：

```
卡字要求：关键词前 1.35 秒画面安静
场景淡入：0.30 秒

进场必须 ≤ 关键词时刻 - 1.65

如果关键词在段首第 0.5 秒：
  进场要在「段首 - 1.15 秒」→ 落到上一段里
  → 和「上一段还没退场」冲突 → 无解
```

**修法**：**写稿阶段就把关键词放到段首 1.65 秒之后**（第二句，或者段首加一句铺垫）。

**这是唯一能在画画面之前拦住的地方。** 到这里才发现，只能改稿重配。

## 坑 12：重复关键词导致索引覆盖

**症状**：两个段落用了同一个关键词，画面只在第一处卡上。

**原因**：用 `word` 做 key，后一个覆盖前一个。

**修法**：用复合键 `{段号}_{序号}_{词}`。

---

## 坑 13：改了文案没重跑对齐，画面全错

**症状**：改了一句稿子，只重配了那一句，画面整体错位。

**原因**：`timeline.json` 是旧的，后面的句子的绝对时间都变了。

**修法**：任何改动文字或停顿，都重跑「拼接 → 对齐 → 渲染」。

**唯一例外**：改停顿（`| 0.5` 的数值）不用重配音，但要重拼 + 重对齐。

# 画面阶段

## 坑 14：判断当前场景用 `from` 而不是 `inFrom`

**症状**：场景切换时，主题色和章节号提前跳了。

**原因**：`from` 是「句子开始」，`inFrom` 是「场景开始进场」。判断当前场景要用后者。

**修法**：所有「当前是第几场」的判断都用 `inFrom`。

---

## 坑 15：底色硬切

**症状**：纸白 → 深蓝的瞬间像闪了一下。

**原因**：直接改 `background`，没有过渡。

**修法**：叠一层径向渐变遮罩，0.55 秒扩散。
```css
radial-gradient(circle at 50% 46%, 新色 0%, 新色 ${k*150}%, transparent ${k*150+10}%)
```

---

## 坑 16：动效锚错对象

**症状**：关键词卡不上，但明明有动画。

**原因**：动画做在了容器上，实际视觉变化在被裁切的子元素里。

**修法**：动效要锚在**实际可见的元素**上。

## 坑 17：文字缩放测不出

**症状**：`scale 0.94 → 1` 的动画，卡字率检测说没动。

**原因**：在 192×108 缩放下，6% 的面积变化被稀释了。

**修法**：见坑 20（呼吸遮罩）。

## 坑 18：`outTo` 被下一场的 `inFrom` 压缩

**症状**：场景退场太快，还没看清就没了。

**原因**：`outTo = 下一场 inFrom + 0.6`，如果重叠算错，退场被吃掉了。

**修法**：显式计算重叠上限（0.45 秒），双向约束。

## 坑 19：场景重叠超限，主题色串台

**症状**：抽帧发现，段 02 前两格纸白、后两格深蓝。

**原因**：
```python
inFrom = min(kwT - 2.0, from - 0.15)
# 段 03 关键词离段首只有 0.79 秒
# → inFrom 被推到 19.94，而段 02 到 20.77 才结束
# → 重叠 0.83 秒，两个主题同时可见
```

**修法**：`inFrom` 不早于「上一段 outTo - 0.45」。

```python
if i > 0:
    inFrom = max(inFrom, S[i-1].to + 0.22 - 0.45)
```

**0.45 秒的理由**：淡入 0.30 + 余量 0.15。超过 0.5 秒两个主题打架。

## 坑 20：小动作在灰度检测下等于没动（**最重要**）

**症状**：卡字率只有 60%（9/15），6 个场景全部失败。

**原因**：

| 场景 | hit 时刻在做什么 | 面积变化 | 倍数 |
|---|---|---|---|
| hero | 标题 `scale 0.94→1` | 6% | 0.8x ✗ |
| quote | 文字上移 20px | 位移不改面积 | 0.9x ✗ |
| before-after | `scale 0.92→1` | 8% | 0.8x ✗ |
| number | 数字滚完就停 | 0% | 1.0x ✗ |
| cta | 按钮早出现完了 | 0% | 1.0x ✗ |

卡字率检测缩到 192×108 灰度比像素。这些「小动作」在缩放下几乎测不出来。

**修法：全屏呼吸遮罩。**

```js
// 在 build() 里，upd() 之后加
const overlay = document.createElement('div');
overlay.style.cssText = 'position:absolute;inset:0;pointer-events:none;z-index:20;opacity:0';
sc.appendChild(overlay);

update: (time) => {
  inner(time);
  const inWin = time >= hit - 0.35 && time <= hit + 0.15;
  if (inWin) {
    const wob = 0.07 + 0.05 * Math.sin((time - hit) * 38 + 1.2);
    const dark = (theme === 'dark' || theme === 'red');
    overlay.style.background = dark
      ? `rgba(255,255,255,${wob})`
      : `rgba(26,28,31,${wob})`;
    overlay.style.opacity = 1;
  } else {
    overlay.style.opacity = 0;
  }
}
```

**实测效果：60% → 100%。**

| 段 | 加之前 | 加之后 | 倍数变化 |
|---|---|---|---|
| 01 | 0.70% | **15.28%** | 0.8x → **16.6x** |
| 06 | 0.05% | **13.90%** | 0.8x → **231.7x** |
| 15 | 0.49% | **9.72%** | 1.0x → **19.1x** |

**⚠️ 关键参数**：
- 振幅 **0.07 ± 0.05**（太小测不出，太大晃眼）
- 频率 **38 rad/s**（60fps 下每帧变 0.04-0.06）
- **暗底用白遮罩，亮底用黑遮罩**

**⚠️ 必踩的坑**：`overlay` 必须在 `upd()` **之后**加。
场景的 `upd()` 里是 `sc.innerHTML = ...`，会清空所有子节点。

## 坑 21：`font: 700 300px/1 inherit` 让整条简写失效

**症状**：写了 300px 的字，实际渲染 16px。

**原因**：`inherit` 不能作为 `font` 简写的字体族。

**修法**：显式写字体族，而且**用单引号**。

```css
font: 700 300px/1.05 'PingFang SC','Microsoft YaHei',sans-serif;   /* ✓ */
font: 700 300px/1.05 "PingFang SC",sans-serif;                     /* ✗ */
font: 700 300px/1.05 inherit;                                       /* ✗ */
```

**验证方法**：必须用 `getComputedStyle` 查一次，不能靠眼看。

---

## 坑 22：字体族用双引号截断 `style` 属性

**症状**：`Layout` 算出 260px，实际渲染 16px，**不报错**。

**原因**：

```html
<!-- 双引号提前闭合 style，整条 font 失效 -->
<div style="font:700 260px/1.08 "PingFang SC",sans-serif">
<!-- 浏览器解析成：style="font:700 260px/1.08 " 然后 pingfang=... -->
```

**修法**：**内联 style 里的字体族必须用单引号。**

```html
<div style="font:700 260px/1.08 'PingFang SC',sans-serif">   <!-- ✓ -->
```

**这个坑本项目踩了 3 次。**

## 坑 23：`anim.js` / `time.js` 污染全局

**症状**：`Identifier 'clamp' has already been declared`。

**原因**：两个文件在顶层声明了 `clamp, lerp, inv, E, springTo, bell` 等，和画布重名。

**修法**：两个都用 IIFE 包起来，只挂 `window.Anim` / `window.Time`。

# 声音阶段

## 坑 24：响度永远到不了 -14 LUFS

**症状**：混音后只有 -18.3 LUFS，想加 4.3 dB 但峰值会到 +2.8 dBTP。

**原因**：TTS 输出峰值高（-1.2 dBFS）、RMS 低（-23），动态 20 dB。

**三套方案实测对比**：

| 方案 | 结果 | 判定 |
|---|---|---|
| `loudnorm` 两遍法 | -16.4 LUFS | ✗ 差 2.4 |
| `acompressor` + makeup 单独 | 峰值超限 | ✗ |
| **压缩 + 限幅 + 精确增益** | **-14.0 / -2.4** | **✓** |

**正确参数**：
```bash
# ① 压缩：阈值 -24 / 比例 4 / makeup 14
ffmpeg -y -i narration.wav -af \
  "acompressor=threshold=-24dB:ratio=4:attack=5:release=150:makeup=14" \
  -ar 48000 _c.wav

# ② 硬限幅：0.87 = -1.2 dBFS
ffmpeg -y -i _c.wav -af \
  "alimiter=limit=0.87:attack=2:release=30:level=0" \
  -ar 48000 _l.wav

# ③ 精确增益：gain = min(-14.0 - 当前LUFS, -1.2 - 当前dBTP)
ffmpeg -y -i _l.wav -af "volume=+X.XdB" -ar 48000 mix-final.wav
```

**为什么 `loudnorm` 不行**：`linear=true` 在 LRA 大时限制增益。实测 LRA 9.3，只能到 -16.4。

## 坑 25：每句音量差 12 dB，整段归一化没用

**症状**：整段 -18.7 LUFS，但后面 1/4 明显小声。

**原因**：TTS 每句输出音量不一致。

```
1.5s  RMS -18.4
17.0s RMS -17.3
20.5s RMS -29.2   ← 小了 12 dB
24.0s RMS -24.4
```

**修法**：**逐句 RMS 归一化**。

```python
def normalize_rms(x, target_db=-23.0):
    rms = float(np.sqrt(np.mean(x ** 2)))
    cur_db = 20 * np.log10(rms)
    gain = 10 ** ((target_db - cur_db) / 20)
    y = x * gain
    LIMIT = 10 ** (-3.0 / 20)      # ⚠️ -3 dBFS，不是 -1.5
    pk = float(np.abs(y).max())
    if pk > LIMIT:
        y = y * (LIMIT / pk)
    return y
```

**实测效果：句间差 12 dB → 2.3 dB。**

**⚠️ 峰值上限必须是 -3 不是 -1.5。** -1.5 会触发钳制，RMS 归一化失效（实测每句峰值都被钉在 -1.5，RMS 还是差 2.7 dB）。

## 坑 26：归一化读自己输出，越跑越小声

**症状**：重跑一次，响度从 -18.3 变成 -23.3。

**原因**：归一化的源是 `mix-final.wav`（上一次的输出），又叠了一次增益。

**修法**：归一化的源永远是 `narration.wav` 或 `mix.wav`，**并且先删旧的 final**。

```python
final_audio = DEMO / "mix-final.wav"
if final_audio.exists():
    final_audio.unlink()      # 必须删
```

## 坑 27：音效按人声峰值校准会太响

**症状**：音效和人声一样响。

**原因**：文档写「落点峰值 = 人声峰值 -5.5 dB」，但那隐含人声峰值约 -4.5 dBFS。

**这段旁白峰值是 -1.2 dBFS（TTS 原始输出顶满）**，-5.5 就变成和人声一样响。

**修法**：按 **人声 RMS - 8 dB** 校准。

## 坑 28：BGM 动态太大，让位不均匀

**症状**：同样 -15 dB 的让位，有的段落听不见 BGM，有的盖住人声。

**原因**：BGM 素材本身有 15 dB 波动。

**修法**：先压缩。

```bash

  "acompressor=threshold=-26dB:ratio=4:attack=8:release=180:makeup=3,\
loudnorm=I=-20:TP=-6:LRA=3" _bgm_flat.wav
```

**压缩后波动 4.3 dB，让位才均匀。**

## 坑 29：用相减估算分层音量，结论全错

**症状**：算出 BGM 比人声响 2.6 dB，但实际听是 -14.8 dB。

**原因**：混音做了峰值保护（整体缩放），`mix.wav - narration.wav` 会混进缩放误差。

```

# 通用

## 坑 30：代码块里的 `#` 被当 Markdown 标题

**症状**：文档里凭空多了几个一级标题，编号全乱。

**原因**：Markdown 把代码块里的 `# 注释` 解析成标题（如果代码块没正确闭合，或者用了全角井号）。

**修法**：代码块里的 `#` 换成全角 `＃`，或者确保 ``` 闭合正确。

## 坑 31：手抄 PLAN 丢了关键词标记

**症状**：画面完全不卡，对齐找到 0 个关键词，而且**不报错**。

**原因**：配音脚本里手抄了一份句子列表，`*关键词*` 的星号在抄的时候丢了。

```
→ selection.json 里的 text 没有星号
→ align 找不到 keywords
→ 画面不知道卡哪里
```

**修法**：**单一数据源**。配音脚本从 `script.md` 解析，不手抄。

```python
PLAN = parse_script(SCRIPT_MD)     # ✓
PLAN = [("01", "第一句话", 0.5), ...]   # ✗
```

## 坑 34：符号链接卡住 Python 的 `rmtree`

**症状**：`OSError: [WinError 1920] 系统无法访问此文件: '...\\.venv\\lib64'`

## 坑 35：渲染器共享浏览器导致崩溃

**症状**：`Target closed` / `Session closed`，6 帧渲染 611 秒。

**原因**：分段渲染时所有段共用一个 browser 实例，页面互相干扰。

**修法**：**每段独立启动浏览器**。

**实测：611 秒 → 27 秒（240 帧）。**

## 坑 36：字幕按字符数切，切出 1-2 字碎片

**症状**：字幕出现「画」这种单字，只显示 0.14 秒。

**原因**：`build_chunks` 用 `len(p)`（元素个数）和 `maxc`（显示宽度）混用，还硬切 16 字。

**修法**：按标点切 → 贪心合并 → 只有单个短语超长才硬切 → 尾部碎片（≤4 字）并回上一块。

**实测：39 块 → 32 块，「显示不到 0.8 秒」6 条 → 1 条。**
